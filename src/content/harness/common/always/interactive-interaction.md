# 互动式交互纪律（interactive-interaction）

> **唯一权威定义**：全项目、全阶段、全部 skill 凡以提问 / 回答、Grill Me、选型对话、确认清单等方式与用户交互时，**必须**遵守本文件。其它约束资产与 skill 正文**不得重复展开**本条全文，仅引用 `common/always/interactive-interaction.md` 即可。

## 必须（MUST）

1. **每次只呈现一个问题**（或一次待确认项）；给出推荐答案或推荐选项，并在末尾明确确认方式（如：是 / 否 / 修改，或接受推荐 / 自定义输入）。
2. **必须等待用户对当前问题完成回答或确认后**，才能提出下一个问题。
3. 用户选择「修改」或要求自定义时，**只处理当前问题**的修订并再次确认；确认通过后再进入下一问题。
4. **针对当前问题必须给出推荐答案**。选项内容与顺序在任何 Coding Tool 下必须一致。怎么呈现以本技能开头的提问声明为准，本文件不重复工具名和编号规则。
   - 推荐答案只有一个时，选项是「接受推荐」和自定义答案。
   - 推荐答案有多个时，每个推荐答案单独占一项。
   - 自定义行是否由界面自动提供，以技能声明为准。

## 禁止（MUST NOT）

1. **禁止**在同一轮回复中列出多个待答问题、编号问题清单、或提前展示「下一题」预览。
2. **禁止**在当前项未确认时，在同一轮或紧接的回复中抛出下一问题（含其它维度、其它步骤的追问）。

## 适用范围说明

- 适用：Grill Me、活动变更 ID 确认、UI 探索问答、技术选型对话、归档 / 棕地分支选择等一切**逐条向用户索取确认**的交互。
- 不适用：非互动式批量输出（如最终文档、检查清单汇总、一次性只读说明），除非其中夹杂未确认的提问。
