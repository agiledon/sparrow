# Grill Me

遵守 harness `common/always/interactive-interaction.md`：每次只问一步，给出推荐答案，确认后再问下一问。能查环境、文档或代码的事实不要问。

确认提示：

```
请确认：是（接受推荐答案） / 否（否定推荐答案） / 修改（提供修改后的答案）
```

某一维度已经清晰时不再追问。该维度全部确认后先总结，再进入下一维度。全部维度覆盖后输出快速总结，再写产出。

## 需求探索（requirement 阶段一）

| 维度 | 说明 |
|------|------|
| 参与者识别 | 哪些角色使用系统 |
| 核心流程 | 每个参与者的主要业务操作 |
| 业务规则 | 重要约束 |
| 边界条件 | 输入输出与外部系统 |
| 异常场景 | 失败与超时处理 |
| 质量属性 | 性能、安全、可用性等非功能需求 |

优先：参与者与核心流程 → 业务规则与边界 → 异常与质量属性。

快速总结须含：全部参与者及职责、核心流程、关键业务规则、主要质量属性。

## UI 探索（requirement 阶段三，可选）

从 `prd-business.md` 的 Actor 推导画像，禁止凭空捏造。

| 维度 | 说明 |
|------|------|
| 用户画像 | 角色属性、目标、熟练度 |
| 核心旅程 | 进入到完成目标的路径 |
| 页面概念 | 旅程触点对应的页面 |
| 视觉偏好 | 风格、色调、密度 |
| 客户端类型 | Web / 移动 / 桌面 |
| 可访问性 | 国际化、无障碍、响应式 |

顺序：画像（按 Actor）→ 旅程 → 页面 → 视觉与客户端。

旅程无断点；禁止孤儿页面（每个页面有进入来源与去向）。落地到 ui-spec 与原型。
